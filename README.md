I like taking ideas that normally need a team — creative-production software, persistent strategy systems, automated game testing, local AI workflows — and seeing how far one developer can push them with modern AI-assisted development.

I care less about generating lots of code and more about making the result **testable, reproducible, recoverable, and actually useful**.

## What I'm building now

### Game-development systems and automation

My current private Unreal research is focused on reusable strategy-game architecture and development tooling: persistent campaign/tactical state hand-offs, deterministic simulation, automated-player missions, real input testing, visual QA/oracles, save/reload proof, and evidence-gated AI-assisted development.

The long-term goal is to make future games cheaper and faster to build by reusing the hard infrastructure instead of starting from zero each time.

**Important:** sponsorship supports my original development work, tooling, research, documentation, and rights-cleared projects. I do not sell access to third-party IP, copyrighted game assets, or private proprietary content.

### [Draft to Take](https://github.com/JaySpiffy/draft-to-take)

A free public beta for local-first script-to-audio production: write or import scripts, prepare voices, generate and review takes, add emotion/SFX/ambience/music, arrange a timeline, and export a finished mix.

### [Void Reckoning Engine](https://github.com/JaySpiffy/void-reckoning-engine)

An experimental persistent 4X campaign and combat simulation framework with evolving factions, strategic AI, campaign economies, tactical combat, reporting, telemetry, and optional Rust/GPU acceleration.

## How I work

- **AI-assisted, not AI-unchecked** — generated work still has to survive tests, review, and real use.
- **Evidence over claims** — if I say something works, I try to back it with a reproducible run or automated check.
- **Reusable systems** — solve the hard problem once, then carry that infrastructure into the next project.
- **Local-first where practical** — creative data should stay on your own machine unless you choose otherwise.
- **Build in public when I can** — failed approaches and rough edges are part of the process, not something to hide.
